# 안심주행 실험

설정 → 주행 → **안심주행 · 실험**. **내비 앱**에서 네이버 지도·티맵·카카오내비 중 설치된 앱을 고른다(기본 네이버). Android 12 이상, 선택한 내비의 설치·초기 설정·위치 및 음량 설정 필요.

1. 잠금을 해제하고 **연결 설정**을 누른다. 개발자 옵션·USB 디버깅·Wi-Fi·앱 알림·개별 알림 채널 중 부족한 조건의 설정 화면을 연다. 해당 조건을 해결하고 앱으로 돌아오면 다음 단계로 이어진다. 변경 없이 돌아오면 같은 화면을 다시 열지 않는다. 케이블 연결은 필요 없다.
2. 필수 설정을 마치면 무선 디버깅 설정을 연다. 무선 디버깅을 켜고 **페어링 코드로 기기 페어링**을 연다. 코드 화면을 닫지 않은 채 알림창을 내려 **코드 입력**에 6자리를 입력한다. IP·페어링 포트·연결 포트는 로컬 NSD로 자동 탐색한다. 접근성 권한은 사용하지 않는다.
3. 저장된 인증이 있으면 코드 없이 연결 준비부터 시도한다. 인증이 만료됐으면 알림의 **설정 열기**에서 새 코드를 표시한다. 탐색이 안 되는 기기는 **수동 페어링 / 연결 포트**를 사용한다. 포트를 비워도 자동 탐색하며 페어링 포트와 연결 포트는 서로 다르다. 알림 설정 요청은 3분 뒤 종료하고 재전송된 과거 알림은 무시한다.
4. USB 디버깅을 켜 두고 무선 디버깅에 사용할 Wi-Fi에 연결한다. 지도 명령 전에는 꺼진 무선 디버깅을 다시 켠다. 선택한 내비의 기존 실행을 종료하고 **5초 뒤 테스트**를 누른 뒤 화면 켜짐 또는 잠금 상태에서 안내 음성을 확인한다.
5. 자동 실행은 **설정 → 차량 → 탑승 감지 블루투스**에서 기기를 직접 선택한 후 별도로 켠다. 휴대·거치 모드 모두 같은 선택을 사용한다. 재부팅·디버깅 데몬 재시작·권한 프로세스 종료 뒤에는 Wi-Fi에서 **연결 준비 / 복구**를 사용한다. 자동 실행을 켜면 Wi-Fi 연결 때 복구를 시도한다.

앱은 휴대폰 잠금을 해제하지 않는다. 셸 권한으로 별도 디스플레이 그룹에 가상 화면을 만들고 선택한 내비의 안심운전 진입점을 전달한다. 내비 응답·음성 성공을 확인하는 API가 없으므로 실행 요청 완료를 음성 성공으로 표시하지 않는다. 화면은 표시용 버퍼만 소비하며 파일·영상으로 저장하지 않는다.

자동 실행은 인증 BLE나 Fleet 호출 없이 기존 A2DP 상태를 사용한다. 해제 30초 후 STOP 명령을 전송하고 완료 응답을 기다린다. 부모 연결이 끊겨도 EOF·15초 심박 만료로 정리한다. 시작 전 선택한 내비 프로세스가 있으면 거절한다. 실험 중 직접 시작한 같은 내비 길안내도 종료 때 함께 강제 종료된다.

ADB는 셸 프로세스를 준비할 때만 사용한다. 이후 셸이 Binder와 소켓 쌍을 전달하고 정확히 같은 앱 UID의 고정 지도 명령만 받는다. 네트워크 제어 포트를 새로 열지 않는다. 앱 프로세스가 다시 생기면 Binder를 재전달하며, 준비 상태 확인은 지도를 실행하지 않는다. 앱이 없는 동안에는 프로세스 목록만 검사한다.

USB 디버깅도 꺼지면 Android가 ADB 데몬과 그 하위 준비 프로세스를 종료할 수 있어, 준비 전에 해당 설정을 검사한다. 앱은 USB 디버깅을 자동으로 바꾸지 않는다.

최초 준비 때 WRITE_SECURE_SETTINGS를 부여받으면 이후 준비·페어링·지도 명령 전에 꺼진 무선 디버깅을 켠다. 기존 Binder를 재사용할 때도 동일하다. 자동 실행이 켜져 있고 선택한 차량 오디오가 연결되어 있으면 준비 완료·실패·수동 지도 종료 후에도 디버깅을 유지한다. 30초 재연결 유예 동안 유지하며 하차 후 STOP 정리까지 끝나면 끈다. 실행 중 꺼지면 기존 3초 심박 명령 전에 다시 켠다. 자동 실행 해제·서비스 종료·차량 밖의 수동 실행 종료 시에는 정리한다. 탑승·실행 중이 아닌 단독 준비·페어링은 완료 후 끈다. 최초 제어 권한을 얻기 전에는 자동 종료할 수 없다. 처음 쓰는 Wi-Fi의 시스템 확인, 개발자 옵션 활성화, 제조사별 설정 화면 차이는 사용자 조작이 필요할 수 있다. 재부팅 후 Wi-Fi 없이 권한을 새로 얻는 기능은 제공하지 않는다. 실제 네이버지도 음성·제조사별 잠금 및 절전 호환성은 실기기 확인이 필요하다.

페어링 코드는 저장·로그 출력하지 않는다. RSA 키는 앱 전용 noBackupFilesDir에 저장하고 연결 호스트는 127.0.0.1로 고정한다. 자동 실행 선택은 일반 설정 백업에 포함하지 않는다. 의존성 고지는 APK의 assets/licenses/wireless-navigation.txt, LGPL 소스는 릴리스의 wireless-navigation-sources.zip에서 제공한다.

## 로컬 회귀 검증

- `./gradlew :app:testDebugUnitTest --tests '*LocalAdbIdentityTest' --tests '*RemovedSafetySettingsTest' --tests '*RoadDeviceIdentityTest'`
- 에뮬레이터 APK: `./gradlew :app:assembleDebug :app:assembleDebugAndroidTest -PhistorySmokeEmulator=true -PsmokeRunner=com.wemade.teslamacro.nav.WirelessNavigationSmokeInstrumentation`
- 지도 대체 APK: `python3 tools/nav-smoke/build_fixture.py`. 실제 네이버지도 대신 가상 화면 진입만 기록한다.
- 프로젝트 상시 승인 범위의 **읽기 전용 로컬 에뮬레이터에만** 대체 APK·앱·계측 APK를 설치하고 임시 ADB 포트를 사용한다. 실제 휴대폰에 대체 APK를 설치하지 않는다.
- 실행기: `com.wemade.teslamacro.test/com.wemade.teslamacro.nav.WirelessNavigationSmokeInstrumentation`. `-e prepareOnly true`로 임시 5557 포트의 앱 내부 ADB 준비를 검사한다. 일반 실행은 Wi-Fi를 연결하고 무선 디버깅을 끈 뒤 연결 불가능한 65534 포트로 바꾸어 Binder 재사용·명령 전 활성화·탑승 중 유지·심박 복구·재연결 유예·하차 정리·수동 종료 유지·자동 실행 해제·반복 실행을 검사한다. `-e pairOnly true`는 접근성이 없는 조건에서 알림 RemoteInput·입력 오류·이전 알림 재전송·TLS 페어링·두 포트 탐색·인증 재사용을 검사한다. 시스템 설정 UI는 테스트 계측에서만 조작한다. `-e recoveryOnly true`는 준비 프로세스가 없는 상태에서 Wi-Fi 도착에 따른 자동 복구와 무선 디버깅 원복을 검사한다.
- 별도 확인: PIN 잠금 유지, 기본 화면과 다른 display ID, 종료 뒤 대체 앱 프로세스 없음, 심박 중단 정리, 기존 실행 보호.
- 지도 대체 앱 검증은 실제 네이버지도 음성 출력의 증거가 아니다. TLS 페어링은 별도 `pairOnly` 결과로 판단한다. 실기기 결과는 설정 → 기기 → 진단 로그 → 공유로 받는다.

카메라 전용 데이터·실행 코드는 제거했다. Settings/Backup의 과거 필드는 구버전 파일 호환용으로만 남고 활성화 값은 항상 false다. DeviceApiClient와 기기 인증 키는 목적지 전송에서도 쓰므로 유지한다. 과거 카메라 개발 도구·로그는 현재 앱 동작에 사용하지 않는다.

- debug/release 각각 앱 481건·BLE 30건 통과, 앱 기존 조건부 제외 13건.

- R8 릴리스 셸/Binder에서 PIN 잠금·반복 실행·STOP·EOF·심박 만료·가상 화면 정리 통과. 계측은 축소 전 Kotlin 클래스명에 의존하지 않는 별도 Java 실행기로 검사한다.
- 처음 시도한 앱→셸 Unix 소켓 연결은 SELinux가 거부해 Binder 전달로 교체했다. 셸의 일반 앱 수신기 등록도 Android가 무시하므로 살아 있는 앱 프로세스 재생성을 확인한 뒤 Binder를 재전달한다.
- 에뮬레이터의 `adb usb`는 기본 5555 포트를 남기고 ADB 데몬을 재시작하면서 하위 준비 프로세스를 종료했다. 이 동작을 Wi-Fi 해제 성공으로 간주하지 않는다. USB 디버깅은 계속 켜 두며 실제 통신은 준비 이후 Binder를 사용한다.
- 자동 설정에서는 중첩 목록 스크롤과 시스템 UI의 네트워크 확인 창을 별도로 처리한다. 설정 도우미를 끄면 예약된 조작도 취소된다.
- 실제 네이버지도 음성, 삼성 등 제조사별 설정·절전·재부팅 전체 과정은 미확인.

## 0.9.180 업데이트 후 준비 프로세스 교체

- 사용자 재현에서 카카오내비 4.51.1은 성공했고 티맵 11.8.3.4061은 일반 내비게이션 화면에 머물렀다. 기기는 SM-S931N, Android 17(API 37)이다. 예약·전달 로그는 있지만 `NAVER_DIAG` 기록이 없어 업데이트 이전 셸 재사용이 의심된다. 이는 티맵 실패 원인의 확정은 아니다.
- `NavigationChannel`의 기존 인증된 Binder에 코드 6을 추가해 셸이 로드한 `BuildConfig.VERSION_CODE`를 확인한다. 앱과 같은 빌드의 AVAILABLE/ACTIVE 서버만 재사용한다. 버전 조회 미지원·불일치인 대기 서버는 기존 ADB 준비 경로에서 같은 소유 UID 프로세스만 교체하고, 새 서버의 버전·대기 상태까지 확인한다.
- 구버전 서버가 ACTIVE이면 교체하지 않고 기존 실험 종료를 안내한다. ADB 연결·인증이 안 되면 최신 프로세스 준비 완료로 표시하지 않는다. 앱/셸 버전과 교체 여부는 공유 진단 로그에 남긴다. 내비 진입 순서·URI·디스플레이·기존 내비 보호·종료 정책은 유지한다.
- 비이미지 전체 테스트·release 빌드 통과. Android 14 일회용 에뮬레이터에서 실제 0.9.179 셸 → 현재 앱 셸 자동 교체와 버전 확인을 검사했다. R8 release 셸에서도 최신 서버의 ADB 없는 재사용, 버전 조회 미지원·불일치 ACTIVE 서버 보존, 구버전 대기 서버의 ADB 연결 불가 시 준비 실패를 확인했다. 실제 티맵 안심주행 성공은 미확인이다.

## 0.9.181 티맵 URI 우선 실행과 점검 5초

- 안심주행 실험과 일반 실행 점검의 예약을 10초에서 5초로 줄이고 버튼·예약 로그를 맞춘다. 실험은 화면을 잠그라는 일회성 안내를 제거하고 제목 도움말에서 화면 켜짐·잠금 상태를 각각 점검하도록 안내한다.
- 셸 화면 관측은 최초 5초로 줄이고 1초 간격으로 조회한다. 변경 상태만 기록하는 상한과 실행·종료 보호는 유지한다. 사용자 로그 공유는 실행 요청 후 5초 대기로 안내한다.
- 티맵이 화면 켜짐 상태에서도 실패했다는 사용자 관측을 반영한다. 현재 실험은 화면 켜짐과 관계없이 가상 디스플레이에 요청하므로 잠금이 실패 원인이라고 단정하지 않는다. 최신 셸의 실제 진입 요청·Activity·디스플레이 기록으로 원인을 구분한다.

- 0.9.180 실기기 로그에서 앱·셸 버전 293 일치와 교체 완료를 확인했다. 티맵은 `MAIN + url=tmap://navi`를 접수한 뒤 가상 화면의 `TmapNewMainActivity`에 머물렀다. 최신 준비 프로세스에서도 일반 화면만 열린다는 사용자 관측이다.
- 티맵은 `ACTION_VIEW`의 data에 `tmap://navi`를 전달하는 후보를 일반 앱·셸 실행 모두에서 먼저 사용한다. 런처 `url` extra는 확실한 거절 때만 대체로 사용한다. 카카오·네이버 순서와 불명 응답의 재실행 금지는 유지한다. URI 접수는 실제 안심주행 성공을 뜻하지 않는다.
- 비이미지 테스트: app debug/release 각 529개(13개 기존 skip), tesla-ble 각 30개, 실패·오류 0. release arm64 빌드·서명 확인 통과. Android 14 일회용 에뮬레이터와 R8 셸에서 URI 접수 시 런처 중복 요청 없음, URI 명확 거절 시 런처 대체, 일반 앱 후보 순서, 5초 예약, 공유 로그 수신, 5초 뒤 관측 중단, STOP 정리를 검사했다. 실제 S25·티맵 11.8.3.4061의 안심주행·음성 성공은 미확인이다.
